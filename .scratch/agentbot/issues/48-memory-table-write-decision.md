# 48 · 记忆落库与写入决策

- **Feature**: F-87
- **里程碑**: M3
- **Status**: resolved
- **Blocked by**: 45
- **写域（建议）**: internal/store/, internal/agent/memory.go, internal/agent/automemory.go

## 目标

记忆从 JSONL 搬进 @BT@memories@BT@ 表，并把写入从"近似去重后追加"升级为
**新增 / 更新 / 忽略**的显式决策。

## 交付物

- @BT@memories@BT@ 表：@BT@scope_key / kind / title / text / source_refs / score / 内容指纹@BT@
- 写入决策函数：输入新事实 + 同作用域既有条目，输出 新增/更新/忽略 及**理由**
- 既有 Jaccard 去重保留为判据之一，但结论必须可解释（给出相似度与命中项）
- 排序确定性（同分按 id），保证注入渲染逐字节稳定
- 作用域参与**所有**读写路径

## 验收

- 同一事实不同措辞写两次只有一条；两个不同事实都保留
- 更新既有条目后注入顺序不变（就地更新）
- 跨作用域隔离有测试
- 内容指纹保证重放幂等
- 误合并对照用例：语义不同但共享词较多的两条不得被合并

## Comments

### 2026-10-03 · 完成记录

**中途改了方案（经用户确认）**。原计划用字符相似度 + 阈值做写入决策，但实测暴露了它的根本局限：

| 文本对 | 相似度 | 原判据 |
|---|---|---|
| `旧的一条` vs `新的一条` | **0.50** | ❌ 被合并——**两件不同的事** |
| `我喜欢喝橙汁` vs `用户喜欢喝橙汁` | 0.57 | ✅ 合并（正是要修的重复） |
| `我喜欢喝橙汁` vs `我喜欢喝冰美式` | 0.43 | ✅ 不合并 |

阈值的两难：调高到 0.6 会让 0.57 那个真重复漏掉；保持 0.5 又会误合并短文本。
根因是**短文本的二元组太少，Jaccard 噪声极大**（4 个字只有 3 个二元组）。

用户提出的方向：**用不开思考的模型辅助判断**。最终形态是**混合判定**：

```
① 指纹完全相同          -> 忽略（确定性，幂等，不问模型）
② 相似度 >= 0.90        -> 并入（确定性）
③ 相似度 <  0.30        -> 新增（确定性）
④ 0.30 ~ 0.90 歧义带    -> 问语义判官；判官失败则退回确定性阈值
```

三点设计考虑：
- **大多数写入不付额外调用**：字符相似度足以处理明显的情况，只有真正含糊的那一小撮才问。
- **判官结果按文本对缓存**：同一对永不重复询问。这既省调用，也保证同一输入永远得到同一结论
  ——记忆内容会进入提示词前缀，结论漂移会让前缀无谓地变化（ADR-0002）。
- **判官只是"更准"，不是"必须"**：失败时退回确定性阈值（用户选定的语义），
  **写入照常成功**，不因判官故障丢记忆。

**确定性判据同时加固**：`textsim.IsDuplicate` 增加最短长度门槛（双方 ≥6 字才用相似度，
更短的只认完全相同）。理由与整体方向一致——确定性层必须**保守**，
宁可漏合并（用户看得见的重复）也不误合并（看不见的记忆丢失）。

**交付物**
- `memories` 表：`scope_key / kind / title / text / source_refs / score / fingerprint`
- `Store.SaveMemoryWith`：支持 `ForceMergeID` / `ForceAdd`，让上层把语义结论传进来
- `Store.FindSimilarMemory`：给上层做歧义判断用
- `internal/memory`：`Store`（混合决策）、`Judge` 接口、`LLMJudge`（关闭思考 + 判答缓存）
- `internal/textsim`：相似度算法下沉成中性包（存储层与 Agent 层都要用，
  放在任何一方都会造成反向依赖）
- `store.ImportMemoriesJSONL`：旧记忆文件幂等导入
- 配置 `agent.memory_judge.enabled`

**顺手修掉的真 bug**：`TrimMemories` 的淘汰顺序写反了——`ORDER BY score ASC ... OFFSET keep`
删掉的是**分值最高**的记忆（正好删反）。已改为按好到差排序后跳过前 keep 条。

**验收执行**（`go test ./internal/store/ ./internal/memory/ ./internal/textsim/` 全绿）
- 确定性快路径：完全相同不问判官；明显不同直接新增
- **歧义带**：判官说不同 → `旧的一条/新的一条` 两条都保留；
  判官说相同 → `我喜欢喝橙汁/用户喜欢喝橙汁` 并入一条
- 判官失败 → 退回阈值且**写入成功**，回退次数可观测
- 判答缓存：同一对文本只问一次
- `ParseVerdict`：是/是的/否/不一样/不是/no/yes 正确；空与无法解析报错
- 就地更新保持 id 与顺序（注入顺序不位移）
- 跨作用域隔离；空作用域**拒绝写入**而非串在一起
- 淘汰：分值最低的先走，高分条目保留
- 冒烟：真实 `memory.jsonl` 导入 4 条，判官启用日志正确

**未做**：`source_refs` 目前只是列，尚未回填原始对话引用（F-48 的书签语义）。
