# ADR 0002 · 记忆注入位置：system 之后、历史之前

- 状态：已接受
- 日期：2026-10-03
- 关联：F-40（save_memory）、F-44（memory_recall）、F-48（长期记忆）、F-65（前缀缓存）、internal/conversation
- 取代：无
- 对应 spec §6 新增登记项

## 背景

F-40 的验收要求"`save_memory` 写入成功后在下次会话的提示词中出现该记忆"。
而当前"缓存优先"布局把上下文切成三段——不可变前缀（system）+ 只追加历史 + 当前输入——
其收益完全建立在 **system 逐字节不变**之上。

实测（deepseek-flash）：前缀约 1650 token 时，完全相同的第二次请求命中 84.9%，
追加一轮后 91.9%；而前缀一旦变化，其后全部内容失效。

- 若把记忆并入 system：每次记忆更新都让**整块缓存报废**，包括所有会话共享的那份大头。
- 若把记忆放到最末尾：system + 历史的前缀始终稳定，但记忆每轮都按未命中计费。

## 决策

**记忆作为独立消息放在 system 之后、历史之前。**

```
[system 不可变] [记忆 可变] [历史 只追加] [当前输入]
```

- 记忆不进 system，因此 system 仍是全局共享的稳定前缀
- 记忆更新时只失效"记忆之后"的部分，system 段仍然命中
- 记忆长度上限取 F-47 的规定：**单条 500 字符**；内容必须**确定性排序**，
  否则同一次写入的两次渲染不同，会平白多失效一次
- **记忆必须按作用域隔离**（F-47）：作用域经 ctx 传递（`WithMemoryScope`），
  会话键即作用域。不隔离的话，私聊里存下的内容会被注入群聊的提示词——这是隐私缺陷

## 后果

正面：

- 保住 system 段的全局缓存收益
- 记忆更新频率远低于对话轮次，代价可接受

代价：

- 历史段（排在记忆之后）在每次记忆更新时失效一次
- 记忆本身不被缓存，每轮按未命中计费——但它通常很短

## 备选方案与否决理由

- **并入 system**：记忆更新即全量失效，否决。
- **放在最末尾（当前输入之前）**：system + 历史最稳，但记忆每轮都未命中且位置随历史浮动，
  否决。
- **不常驻注入、只提供 memory_recall 工具**：这是 F-44 的 `memory_recall`，
  与本决策互补而非替代——常驻记忆仍需注入。
