# 提示词资产目录

本目录存放人格（system prompt）等提示词资产，路径由 `prompt.dir` 配置。

## 用法

```yaml
llm:
  system_prompt_file: prompts/<你的文件>.md
```

服务启动时**只读一次**并固定为"不可变前缀"——运行中读文件可能拿到改动后的内容，
那会让前缀在运行中变化，DeepSeek 的前缀缓存全部失效。

## 为什么单独放文件

- 长人格提示词写在 YAML 里很难维护，单独成文件便于编辑与版本管理
- 与解析逻辑分离：提示词是内容，不是代码

## 写提示词的两条经验（实测所得）

1. **提示词自己不要用 Markdown**。模型会模仿系统提示词的排版——一边用 `-` 列表写
   "不许用列表"，一边指望它不输出列表，是自相矛盾的。用 `【小节】` + 纯文本行。
2. **前缀越长，缓存收益越大**。实测（deepseek-flash）前缀 53~77 token 时命中率恒为 0%；
   约 1650 token 时，完全相同的第二次请求命中 84.9%，追加一轮后 91.9%。
   而这段前缀是**所有会话共享**的，只付一次未命中的钱。

## 关于本仓库

具体的私有角色人格（例如 `xiangcheng-niang.md`）已被 `.gitignore` 排除，不入库。
请自建文件，或把 `config.example.yaml` 里的 `system_prompt` 内联示例改成你自己的角色。
